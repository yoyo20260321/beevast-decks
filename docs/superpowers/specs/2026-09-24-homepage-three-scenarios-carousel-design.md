# BeeVast 官网三个典型行业场景轮播设计

日期：2026-09-24  
范围：`beevast-home-v4/index.html` 的“典型行业场景”模块  
状态：用户已确认 D 版——沿用官网现有轮播，不设置体验入口

## 1. 目标与成功标准

吸收最新宣发 Demo 的可信内容，把官网目前单一的“智能售后客服”场景更新为三个同权轮播场景：

1. 智能客服工作台；
2. 来料质检分析；
3. 交付风险预警。

完成标准：

- 三个场景均可通过箭头、圆点和触控切换，交互习惯与下方“真实案例”轮播一致。
- 每个场景讲清业务问题、三步工作链路、Pilot 验证指标和人机边界。
- 场景模块不出现“体验 Demo”“查看详情”等跳转入口；全站转化继续统一收口到现有“预约 30 分钟场景诊断”。
- 场景轮播与真实案例轮播职责明确：前者说明“怎么工作”，后者提供“客户结果与证据”。
- 桌面和移动端均无横向溢出，键盘、箭头按钮、圆点及 reduced-motion 状态可用。

## 2. 内容结构

每个轮播页采用相同信息骨架：

- 行业与场景标签；
- 场景标题；
- 一段业务问题与人机协作说明；
- 三步工作链路；
- 三至四项 Pilot 验证指标；
- 对应产品界面截图。

不写未经客户或项目证据验证的收益承诺；Demo 中的示意数据只用于说明工作方式，不转写为官网实绩。

### 2.1 智能客服工作台

- 标签：跨境电商 / 智能客服。
- 说明：跨语言接待、知识检索、快速建单与人工协同；高风险承诺由人工确认。
- 链路：识别诉求 → 知识回复 → 建单 / 转人工。
- 验证指标：首次响应时间、一次解决率、人工介入率、新人独立接待周期。
- 仓库素材：`demos/scenario-1-cs.png`；页面引用：`../demos/scenario-1-cs.png`。

### 2.2 来料质检分析

- 标签：制造业 / IQC 来料质检。
- 说明：批量解析检验报告与料号，按图纸和规则判定；临界项由质检人员确认。
- 链路：报告归一 → 规则判定 → 临界复核 / 回写台账。
- 验证指标：报告处理时长、规则命中率、临界项复核率、台账完整率。
- 仓库素材：`demos/scenario-2-qc.png`；页面引用：`../demos/scenario-2-qc.png`。

### 2.3 交付风险预警

- 标签：制造业 / 供应链交付。
- 说明：汇总订单、库存、来料和排程数据，识别红黄蓝风险；处置与销项由责任人确认。
- 链路：多源归一 → 风险分级 → 责任推送 / 闭环跟踪。
- 验证指标：OTD 准时交付率、物料齐套率、预警提前量、逾期消化周期。
- 仓库素材：`demos/scenario-3-delivery.png`；页面引用：`../demos/scenario-3-delivery.png`。

## 3. 视觉与交互

- 沿用当前官网暖白背景、白色主卡、16px 左右圆角、低对比边框与轻阴影。
- 桌面端为“左侧文字、右侧产品截图”；移动端改为“截图在上、文字在下”，不缩成难读的双栏。
- 场景卡一次只展示一页，底部使用左右箭头与三枚圆点；当前圆点使用品牌主色和拉长胶囊形态。
- 默认展示智能客服；场景轮播不自动播放，避免与下方案例轮播同时抢动。用户只通过箭头、圆点、键盘或触控主动切换。
- 轮播切换保留克制的透明度/位移动效；`prefers-reduced-motion` 下直接切换。
- 产品截图只承担“界面是什么样”的说明作用，不可点击，不出现伪按钮或体验暗示。
- 轮播容器提供可访问名称；箭头与圆点均使用原生 `button`。活动圆点设置 `aria-current="true"`，每页提供“当前序号 / 总数 + 场景名”的可访问标签；非当前页不得被键盘聚焦或被读屏重复读取。

关键取舍：

- 放弃三卡并列：与官网现有内容节奏不协调，且移动端会形成过长卡片堆叠。
- 放弃标签切换：非首屏场景发现性较弱。
- 放弃 Demo 入口：用户明确要求不提供体验入口；转化统一由官网预约入口承担。
- 保留真实案例为独立轮播：场景与证据不混写，避免把演示口径误当客户结果。

## 4. 实现边界

- 修改 `beevast-home-v4/index.html` 内典型场景的 HTML、局部 CSS 和轮播脚本，并为 `scripts/verify-home-v4.mjs` 增加本轮静态断言。
- 复用仓库已有三张场景截图，不增加外部图片、字体、脚本或网络依赖。
- 不改三套 Demo 页面、不改真实案例正文、不改预约表单、不增加新路由。
- 复用或抽取现有案例轮播的通用行为；避免复制互相冲突的全局选择器和计时器。
- 场景轮播使用独立 ID 与 `data-*` 属性，避免影响案例轮播。
- 现有验证脚本的 `htmlGzipBytes <= 24000` 性能预算保持不变；新增内容必须通过复用结构、收紧冗余标记以及压缩当前首页内联 CSS/JS 来抵消，禁止以调高阈值通过验证。
- 场景静态首帧不得依赖现有 `.reveal` 才可见；避免给首帧容器套用该类，或提供可验证的 no-JS 回退。

## 5. 状态与错误处理

- JavaScript 不可用时，首个场景的标题、说明、三步链路、指标和截图保持完整可读，其余场景不遮挡首帧内容。
- 截图加载失败时保留明确的 `alt` 文本和稳定容器尺寸，页面布局不塌陷。
- 轮播索引循环处理：第一页向前回到第三页，第三页向后回到第一页。
- 场景轮播无计时器，不受页面可见性变化影响。

## 6. 验证

- 运行 `node scripts/verify-home-v4.mjs` 与 `git diff --check`；`htmlGzipBytes` 必须不超过 24,000 B。
- 扩充验证脚本静态断言：三个场景标题和三张相对路径素材存在；场景轮播容器与案例轮播 ID/控制器隔离；不存在“体验 Demo”“查看详情”等场景跳转入口；活动圆点状态使用 `aria-current`。
- 检查 1440×900、860×900、640×900、420×860 四个视口，无横向溢出或文字遮挡。
- 逐项验证场景箭头、圆点、键盘 Enter/Space、触控滑动和循环切换；活动圆点、页标签与非当前页的读屏/聚焦状态同步正确。
- 验证下方真实案例轮播仍能独立工作，两个轮播的按钮和圆点不串联。
- 验证 reduced-motion 下内容立即可见且切换不依赖动画。
- 验证三个截图均来自仓库相对路径，页面无新增第三方请求。
- 禁用 JavaScript 后验证首场景标题、说明、三步、指标和截图均可见。
- 完成后在开发预览域名复核；正式官网发布前由 owner 再确认。

## 7. 风险与回退

- 风险：同页两个轮播若复用选择器不严谨，可能互相切换。通过独立容器初始化和局部查询规避。
- 风险：截图宽度增加页面体积与移动端首屏加载压力。保持现有 WebP/JPEG/PNG 资产，不生成新大图；非首张截图使用原生懒加载。
- 风险：自动轮播同时运行造成视觉干扰。场景轮播在用户交互后停播，并遵守 reduced-motion。
- 回退：该改动限定在单个首页文件与既有静态素材引用；如验证失败，可对本分支提交执行 `git revert`，不涉及数据迁移。
