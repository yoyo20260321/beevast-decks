# 智能客服工作台 UI/UX 重设计规格

日期：2026-09-24  
目标页面：`demos/scenario-1-cs.html`  
设计方向：B · 克制型企业服务台

## 1. 目标与边界

把当前偏“AI 演示大屏”的界面重做为可信、克制、可操作的企业级客服产品原型。保留会话、多语言、快速建单、转人工、数据分析及现有示意数据，不新增后端、账号体系或真实业务接口。

成功标准：

- 第一眼能识别当前客户、问题状态、下一步动作与风险边界。
- 主操作“审核并发送”始终明确，次要动作降权但可达。
- AI 输出同时展示依据、置信度或人工审批边界，避免“魔法感”。
- 1440×900 桌面端完整可用；1024px 宽度下不遮挡核心操作；手机端能浏览和完成会话、建单。
- 键盘可操作，焦点可见，满足 WCAG 2.2 AA：正文对比度至少 4.5:1，大文本和非文本控件至少 3:1。

## 2. 视觉系统

- 基调：浅色中性工作台；深灰导航、暖白内容面、低饱和青绿色作为唯一主品牌色。
- 去除大面积霓虹蓝、发光、渐变、虚线 AI 边框、同权重卡片和无意义悬浮动效。
- 使用 8px 间距体系、6/8/12px 圆角三级、克制阴影；边框承担分区，颜色只表达状态。
- 字号层级：页面/会话标题 16–18px，正文 13–14px，辅助信息不低于 12px。
- 状态语义：绿色=已完成/安全，琥珀=待确认，红色=风险/升级，青绿=当前主动作。

## 3. 信息架构与组件

页面继续采用单文件静态实现，结构调整为：

1. 顶栏：品牌、回复语言、在线状态、快速建单；不新增无真实行为的搜索和帮助入口。
2. 左侧导航：仅“会话工作台、数据分析”可切换；工单、知识库、话术、设置统一为禁用态并说明“演示版暂未开放”。当前项使用实底标识，不使用空心方块假图标。
3. 会话工作区：
   - 会话头：客户身份、渠道/语言、问题标签、SLA、转人工。
   - 消息流：区分客户、AI 草稿、系统动作；系统动作使用审计时间线，不伪装成聊天气泡。
   - 处理建议：把“已查订单、推荐动作、风险控制”做成紧凑证据栏。
   - 编辑器：回复草稿、依据来源、可编辑输入、审核并发送、创建工单。
4. 右侧上下文：客户与订单、处理依据、历史工单、今日效率；1200px 以下收进可展开抽屉。
5. 数据分析：沿用现有图表数据，统一浅色视觉、增加口径提示、减少装饰动画。
6. 建单弹层：分成“AI 已提取信息”“人工确认字段”“执行结果”三段，保留编辑能力与审批说明。

## 4. 交互与数据流

- 单文件状态模型包含：`activeConversation`、`replyLanguage`、各会话消息/编辑器草稿/发送状态/转人工状态/工单列表，以及全局分析周期、图例开关和选中客诉类型。状态仅存于本页内存，刷新即恢复初始演示数据。
- 切换会话时保存并恢复该会话的消息、未发送编辑器内容、转人工结果和已建工单；分析筛选保持为全局状态。
- 回复语言支持中文、英语、俄语，默认中文；切换只改变当前 AI 回复草稿及输入提示，不翻译历史客户原文、客户身份、业务字段或整个产品界面，避免伪造全量国际化能力。
- 发送：优先发送编辑器内容；为空时使用当前语言草稿。点击后按钮短暂进入“发送中”并禁用重复提交，完成后显示发送结果；不伪造长时间 AI 思考。
- 转人工：首次操作显示已分派结果与责任人；已转人工后按钮变为不可重复操作的状态，并保留会话记录。
- 建单：打开弹层后显示固定约 600–900ms 的本地提取状态，期间提交按钮禁用，随后填入可编辑字段；必填字段为空时就地提示。创建期间禁止重复提交，完成后更新工单徽标、消息时间线和成功提示；取消不写入状态。
- 数据分析：7/30 天切换、图例筛选、类型明细保持现有能力；可点击区域补充键盘行为和 `aria` 标签。
- 未开放导航项保持禁用态并说明“演示版暂未开放”，不制造可点击但无结果的假入口。
- 空/边界状态：无会话时显示可恢复的空态；无历史工单显示“暂无历史工单”；图表无数据时显示口径与空态，不绘制误导性零值图；已转人工会话仍允许查看，但发送与重复转人工禁用。

## 5. 响应式与异常状态

- ≥1200px：三栏完整工作台。
- 900–1199px：窄导航 + 主工作区；右侧上下文由会话头按钮打开抽屉。
- <900px：单栏；导航由顶栏菜单打开，消息/编辑器优先，主操作区吸底，右侧上下文继续以抽屉呈现，数据图表改单列，建单弹层全屏化。
- 不依赖网络资源；字体使用系统栈。JS 发生非关键错误时，静态内容与核心发送/建单入口仍可见。
- `prefers-reduced-motion` 下关闭数字补间和位移动画。
- 建单弹层和上下文抽屉打开后焦点进入首个有效控件并圈定在容器内；Esc 关闭，关闭后焦点回到触发按钮。

## 6. 实现约束

- 继续维护为一个 HTML 文件，避免为单页演示引入组件框架、构建工具或第三方依赖。
- 不改变 GitHub Pages 路径，不新增外部字体、图标 CDN 或数据请求。
- 现有示意指标继续标注“示意数据”和计算口径；不把其表达为真实客户结果。
- 使用语义化 `button`、`nav`、`main`、`aside`、`dialog`/等效 ARIA，不再用 `span` 模拟按钮；状态同时使用文字/图标表达，不仅依赖颜色。图表提供简短文本摘要或可读数据列表。

## 7. 验证

- 回归基线：保留 3 个会话及其客户/单号/问题/消息/草稿；中文、英语、俄语回复切换；建单客户、关联单号、类型、优先级、标题、描述、建议处置字段；转人工反馈；4 个 KPI、处理时长趋势、解决构成、客诉类型和类型明细；7/30 天、图例开关、类型筛选均可用。
- 功能：会话切换、语言切换、空草稿发送、防重复提交、转人工及重复操作、建单校验/取消/创建、无数据状态、7/30 天切换、图例和类型明细逐项验证。
- 视觉：1440×900、1024×768、390×844 三档截图检查，无溢出、遮挡、过小文本或不可见控件。
- 可访问性：Tab 顺序、Enter/Space、弹层初始焦点与焦点圈定、Esc 关闭及焦点恢复、按钮名称、图表摘要、对比度逐项检查。
- 发布：沿用仓库既有 GitHub Pages，从 `main` 分支根目录发布；目标 URL 为 `https://yoyo20260321.github.io/beevast-decks/demos/scenario-1-cs.html`。所有资源保持相对路径或内联；分支评审后合并，确认页面返回 200、页内版本标识更新、核心交互可运行且控制台无阻断错误。

## 8. 明确放弃

- 放弃暗色霓虹“AI 驾驶舱”视觉，换取更可信的企业软件感。
- 放弃所有信息同时常驻，换取小屏与主任务聚焦；次要上下文按需展开。
- 放弃组件框架和构建链，换取单文件可审阅、可直接托管。
- 放弃后端持久化、真实搜索/帮助、真实异步 AI、工单和转人工接口；所有结果均为本地确定性模拟，当前交付只验证产品体验和业务动线。
