# 作业问题与需求聚焦、角色/Agent/执行三级下探

admin5确认上一轮角色三级展示方案，并补充：及时掌握问题/阻塞/人决策，查看单需求/单任务作业。仅Mock演示，不接实际Agent运行或改变平台预算。延用单HTML、现有工作树/分支、独立复核后原公网静态投放。

## 数据与规则
- 角色是职责，Agent是稳定身份，执行是有独立ID/任务/版本/阶段/开始/结束/心跳的记录。默认开发A/B各1执行；质量A可承载2会话但默认角色准入限1，只有显式Mock并发场景才模拟qa/test各2。聚合分别数Agent、活跃执行、未知占用、等待与上限，未知占槽不释放。
- 保持现有任务held角色为准入/资源真值，新增作业账本在sample同步，不从卡片索引生成ID。结束/重试保留记录，不给无进度数据的任务编百分比。全局唯一协调1槽单列；人类不是Agent实例。
- 问题来源为模拟状态：未知、当前版本证据不匹配、断线；阻塞含明确外部依赖、停止新准入、实际角色/预算等待、草稿缺输入；待人含范围/发布/验收。待处理数按问题记录计，同时显示去重影响任务数，不相加当任务总数。每条有稳定issueId、原因、任务/需求、开始时间、责任方、影响与处理入口；类别可重叠但不能相加当任务数，按异常/阻塞/决定排序。开始时间来自观察记录，无法确认则标未知，不倒推。
- Mock外部依赖解除须重新核对任务版本/阶段/连接及非空理由，记录解除事件，解除后保留原问题处理记录，显示所解除项、剩余门和下一接收者；之后仍走原准入/质量/人类门，不自动恢复已停止准入。
- 需求ID是稳定归属字段，不由可编辑项目名推导。需求分组不等于依赖边；没有依赖证据不画因果链。

## 界面
- 首页主操作区：处理当前任务、切换视角、待处理（问题/阻塞/待人计数）；故障注入留在演示控制。默认一屏。
- 全局→需求→任务可切换且可返回全局。顶部/地图明确当前范围；任务卡、角色节点计数/灯、推荐行动、流水按范围一致过滤；全局容量与全局曲线明确标“全局”保留，避免假作任务配额。
- 聚焦任务显示当前阶段、执行者、阻塞/待人、下一接收者；点击Agent默认沿用聚焦范围，显式切换全局历史并可返回当前范围；看该身份当前/历史执行，再点某次执行看版本、状态、心跳、流水/证据和关联任务。默认聚合角色，节点内紧凑实例标记；只高亮选中任务路径，避免铺开交叉线。
- 待处理弹窗有类别筛选、完整问题列表、可点到任务证据/决定；不只闪灯。任务详情追加执行记录、任务全过程流水（本页有上限且说明），可聚焦任务/所属需求；按前后版本区分执行与决定。
- 演示控制提供并发与阻塞场景：开发A/B并发、质量单Agent多会话、外部依赖阻塞、解除后仍受原门约束，数据始终标Mock。
