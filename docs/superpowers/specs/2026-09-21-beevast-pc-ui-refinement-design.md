# BeeVast 官网 PC UI 精修设计

日期：2026-09-21  
范围：`beevast-home-v4/index.html` PC 端视觉精修  
基准视口：1440 × 900；交付整页长图  
状态：用户已确认设计方向 A「全站克制精修」

## 1. 目标

在不改变现有业务信息架构、不新增外部素材的前提下，降低通用 SaaS 与 AI 模板感，使官网呈现更稳重、克制、可信的企业级品牌质感。

完成标准：

- 首屏主次关系明确，标题、说明与转化按钮形成单一视觉路径。
- 字体、间距、圆角、边框、阴影和图标尺度统一。
- “智能售后客服”典型场景与“真实案例”形成明显层级差。
- 关键业务信息与证据口径不被视觉装饰淹没。
- PC 页面通过现有静态校验，1440px 全页截图无溢出、断层或隐藏内容。

## 2. 视觉方向

沿用深海军蓝、暖白与品牌蜂蜜金，但减少渐变、发光和高频装饰。白色区域依靠排版、边框与留白建立质感；深色区域依靠层次化背景与低对比纹理建立空间，不使用浮夸光效。

字体继续使用现有系统字体栈，避免引入第三方字体请求。标题减少过粗字重，正文提高行高与对比度；小字号仅用于辅助说明和数据口径。

放弃：大规模品牌换色、外部插画、新字体和全新页面结构。原因是本轮目标为低风险精修，而非重新设计。

## 3. 页面级调整

### 3.1 首屏

- 收紧主标题最大宽度，建立更清晰的两到三行节奏。
- 增加标题与说明、说明与按钮之间的间距。
- 主按钮保持品牌金，次按钮降低填充与边框对比。
- 产品展示框减少发光和悬浮感，强调真实工作台质感。
- 信任信息与首屏主叙事分离，避免首屏下半部拥挤。

### 3.2 通用区块

- 统一 section 上下留白和标题区宽度。
- 卡片统一圆角、边框、阴影和内边距，减少每张卡都强调的竞争感。
- 图标统一容器尺寸、描边粗细和色彩饱和度。
- 关键数字放大，辅助说明降级，避免卡片内部权重平均。

### 3.3 典型场景

“智能售后客服”保留独立展示，不进入真实案例轮播。其主体采用三段横向业务链路：

1. 客户询问与运单识别；
2. 节点聚合、异常判断与回复；
3. 建单、分派、催办和人工审批。

业务链路是该模块的主要视觉，不再沿用普通案例的 Before/After 表格感。Pilot 指标作为右侧或底部辅助证据区，明确首次响应、一次解决率、新人上手周期、异常闭环时长四项口径。

### 3.4 真实案例

- 保留三个有证据支撑的案例轮播。
- 统一标题、标签、指标和脚注格式。
- 指标区不使用强渐变大字，改为更克制的数据面板。
- 轮播导航降低装饰感，同时保持键盘、鼠标和触控可用。

## 4. 动效与交互

- 保留轻微淡入和卡片悬停反馈。
- 动效位移与阴影变化幅度降低。
- 遵守 `prefers-reduced-motion`，不新增持续漂浮、发光或自动吸睛动画。
- 不改变导航、表单、轮播及移动端既有交互逻辑。

## 5. 响应式边界

本轮以 PC 为主，但不得破坏既有移动端样式。新增或调整的规则优先限定在桌面断点；通用 token 变化需在 860px、640px 和 420px 断点复核。

## 6. 验证与交付

- 运行 `node scripts/verify-home-v4.mjs` 与 `git diff --check`。
- 以 1440 × 900 视口截取完整页面长图。
- 对精修前后长图进行视觉复核，重点检查首屏层级、section 节奏、典型场景/真实案例分层和页脚收束。
- 仅发布开发预览；正式站发布需用户再次确认。

## 7. 风险

- 单文件 HTML 已接近 gzip 体积门槛，新增 CSS 必须通过精简或替换既有规则控制体积。
- 全站 token 调整可能影响移动端，需保持断点验证。
- 现有 reveal 动效可能造成自动长图隐藏未进入视口的内容；截图时使用 reduced-motion 或逐段滚动后再捕获。
