# BeeVast 官网加载速度与 H5 适配设计

日期：2026-09-10  
状态：待 owner 书面确认  
范围：`beevast-home-v4` 单页官网；包含已确认删除“BeeWork AI · 产品能力一览”模块的变更。

## 目标与基线

当前预览页为单文件静态站：HTML 约 91 KB、gzip 后 23,708 B；首屏图 69,536 B；导航 Logo 26,642 B；页面还会请求 15 个第三方字体文件。阿里云 Nginx 已启用 gzip，因此本次不改服务器配置，重点减少前端请求与移动端渲染开销。

验收目标：

- 移除第三方字体网络依赖，首屏不再产生 15 个字体请求；改用系统字体栈，保持现有字重层级。
- 首屏图片增加 WebP 版本；仅在实际体积更小时启用，保留 JPEG 回退。
- HTML gzip 体积不高于当前约 24 KB。“首屏关键静态资源总量”固定定义为 gzip HTML + 首屏图 + 导航 Logo，不计响应头与 TLS；基线为 119,886 B，目标不高于 95 KB 且下降至少 20%。
- 360 / 390 / 430 px 宽度下无横向滚动，核心 CTA、导航、表单和 FAQ 可正常使用。
- iOS 输入框不触发自动放大；底部 CTA 兼容安全区；弹窗不超出动态视口。
- 低性能移动设备减少固定背景、模糊和非必要动画开销；遵守 `prefers-reduced-motion`。

## 方案

### 1. 字体与首屏资源

- 删除 `fonts.font.im` 的样式表、预连接和 `noscript` 回退，统一改为本机系统字体：中文优先 `PingFang SC` / `Microsoft YaHei`，英文优先系统无衬线字体；标题保留系统宋体回退以维持现有气质。
- 为 `hero-poster.jpg` 和导航 `logo-lockup.jpg` 生成较小、按展示尺寸优化的 WebP；通过 `<picture>` 提供 WebP，JPEG 保底。同步预加载实际首选格式，避免重复或无效预加载。
- 保留现有图片宽高，防止布局偏移；页脚和二维码继续懒加载。

### 2. 首屏外渲染

- 对首屏外的主要 section 使用 `content-visibility:auto` 与合理的 `contain-intrinsic-size`，减少首次样式与布局计算。
- 现有内联脚本仍放在文档底部，不新增框架或依赖。
- IntersectionObserver 增加能力检测；不支持时直接展示内容，避免旧版 H5 出现空白。

### 3. H5 适配

- 手机端按钮与导航触控区域不小于 44 px。
- 小屏下收紧首屏间距与字号，CTA 改为易点击的整行布局；卡片与 FAQ 保持单列。
- 输入框字体至少 16 px，避免 iOS 聚焦缩放。
- 弹窗使用 `100dvh` 约束并兼容安全区；底部悬浮 CTA 增加 `env(safe-area-inset-bottom)`。
- 640 px 以下关闭大面积固定装饰层、重模糊和非关键动效，减少滚动掉帧；桌面视觉保持不变。

## 数据流与失败处理

访问路径仍为“浏览器 → Nginx 静态 HTML/图片”，无 API、数据库或用户数据变化。WebP 不被支持时自动回退 JPEG；`content-visibility` 不被支持时按普通 CSS 渲染；IntersectionObserver 不可用时立即显示全部内容。

## 已确认的内容删除

“BeeWork AI · 产品能力一览”已在提交 `572d11f` 从预览源码删除，本轮随性能优化一起进入正式站。原模块边界为 `section#capabilities`（从 `<!-- 产品展示 GALLERY -->` 到客户案例 section 之前）；关联删除包含导航 `href="#capabilities"`、`.cap-*` 专属样式、能力切换脚本以及灯箱中的 `.cap-shot img` 选择器。当前 `index.html` 已不存在这些标识，本轮不得恢复。

## 验证与发布

1. 校验 HTML、JSON-LD、JavaScript 语法、内部锚点、图片路径和备案号。
2. 比较修改前后 HTML gzip、关键资源体积和外部字体请求数量。
3. 校验 360 / 390 / 430 / 768 / 1440 px 的响应式规则与无横向溢出约束；浏览器检查通道恢复时补做真实视口验证，否则以预览页供 owner 实机复核。
4. 先发布 GitHub Pages 预览并验证；owner 明确确认该预览可上线后，写安全操作台账，再同步阿里云并复核 `beevast.com` 与 `www.beevast.com`。

## 关键取舍

- 选择系统字体换取稳定和速度，放弃不同设备上字形完全一致。
- 保留原站单文件架构，放弃引入构建工具与更激进的代码拆分。
- 不改 Nginx 缓存策略，放弃本轮二次访问的极致缓存收益，以缩小生产变更面。
- 不删除服务器上的旧截图资源；它们已不被页面引用，保留可快速回退。
